# Chunk 1 — Voice Pipeline & Gemini Live Conversation — Simplicity & Clarity

**Score: 6/10** — The small pure modules (`audio.ts`, `announcementKinds.ts`, `eventBus.ts`, `announcementBus.ts`) are exemplary and well-factored, but the two big WS message handlers (server `onmessage` tool-call chain and client `connectLive` `onmessage`) are sprawling inline if/else ladders that carry most of the cognitive load.

## Findings

- **server.ts:1486–1890 — one ~400-line inline `if (name === ...) else if` ladder for ~25 Gemini tool calls.** Every branch repeats the same `session.sendToolResponse({ functionResponses: [{ name, id: call.id, response: { output: ... } }] })` boilerplate. This is the single biggest clarity sink in the chunk: the tool-dispatch logic, argument parsing, and response envelope are all interleaved with no table or per-tool function. A dispatch map `{ [name]: (args, ctx) => output }` with one shared response-envelope wrapper would cut this dramatically and make each tool readable in isolation.
- **server.ts:1895 — the `systemInstruction` is a single ~100-line template literal embedded mid-function.** It mixes static prose with live interpolation (`activeProjectId`, workspace list). Hoisting it to a named `buildSystemInstruction(manager)` helper (or a constant + small interpolation) would shrink the connection handler and make the prompt editable without scrolling through session wiring.
- **src/App.tsx:79–178 — `playEarcon` is a 100-line 5-branch synthesizer** with heavily duplicated oscillator/gain boilerplate (`createOscillator` + `createGain` + `connect` + `setValueAtTime` + `exponentialRampToValueAtTime` repeated ~10 times). A small `tone(ctx, {type, freq, at, gain, dur})` helper plus a per-earcon data table (notes/durations) would collapse this to ~25 lines and make the five earcons comparable at a glance.
- **src/App.tsx:904–998 — `connectLive`'s `ws.onmessage` is a ~20-branch `if/else if` string-type switch.** It is followed by the `effectForEvent` fallback (good — that part is already data-driven), but the first ~15 branches (audio/interrupted/approval_pending/prompt_buffer/terminals/ledger/settings/command_auto_executed/command_blocked/stdout/transcript/error/proactive_*) are hand-written. Several do near-identical `playEarcon + triggerDesktopNotification + setX + setTimeout(...,4000)` work and could be partly table-driven like `effectForEvent` already is, reducing two parallel dispatch styles to one.
- **server.ts:1391–1411 — utterance extraction reads `modelTurn.parts`, `turn.parts`, and `userTurn.parts` via three near-identical loops** with `(message.serverContent as any)` casts. The three loops differ only in the source path; a tiny `collectText(parts)` helper applied to each path removes the duplication and the repeated `as any`.
- **src/utils/audio.ts:17–18 — module-level mutable singletons `nextStartTime` / `activeSources`.** Functional but a hidden global; fine for a single playback context, but it means `playAudioChunk`/`resetAudioPlayback`/`isAudioPlaying` are implicitly coupled through file scope rather than an explicit object. Low priority given the file's small size.
- **announcementBus.ts / announcementKinds.ts / eventBus.ts — clean.** `KIND_META` as the single source of truth with derived `EARCON_FOR`/`PRIORITY` projections is exactly the right shape; the bus's seams (injected clock/broadcast) read clearly. No simplification needed here beyond noting these as the model the rest of the chunk should follow.

## Top fixes
1. Replace the ~400-line tool-call `if/else` ladder (server.ts:1486–1890) with a `Record<string, handler>` dispatch table and one shared `respond(call, output)` envelope helper.
2. Collapse `playEarcon` (App.tsx:79–178) into a `tone()` helper + per-earcon data table.
3. Extract the `systemInstruction` literal (server.ts:1895) into a named builder function.
4. Unify the two `onmessage` handlers toward the `effectForEvent` data-driven style; fold the duplicated `playEarcon + notify + setTimeout` notification branches into a small table.
5. Add a `collectText(parts)` helper to remove the three duplicated utterance-extraction loops (server.ts:1391–1411).
