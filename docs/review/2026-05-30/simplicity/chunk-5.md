# Chunk 5 — Ledger, Projects/Knowledge, Orchestration Plans & Settings — Simplicity & Clarity

**Score: 5/10** — `ledger.ts` and `types.ts` are clean; but `SettingsDialog.tsx` re-declares the entire settings shape FOUR times (type + ~24 useState hooks + hydration effect + recompile function + dep array), and the server orchestration tool-handlers repeat the same `sendToolResponse({functionResponses:[{name,id:call.id,response:{output:resp}}]})` boilerplate ~25 times — both are the strongest "delete by restructuring" opportunities in the codebase.

## Findings

- `src/components/SettingsDialog.tsx:100-246` — The settings object is stated four separate ways: (1) ~24 individual `useState` hooks (L100-141), (2) the `useEffect` that hand-copies each `initialSettings.x.y ?? default` into its setter (L162-202), (3) `getCompiledSettings()` that re-assembles them back into one object (L206-246), and (4) the ~20-entry `useEffect` dependency array (L253-256). Adding one settings field means editing five places. A single `useState<SystemSettings>(merge(defaults, initialSettings))` with an `update(path, value)` helper (or per-section reducers) would collapse all four. This is the single biggest simplicity win in the chunk. (36 `useState` calls total in this one component.)
- `server.ts` orchestration handlers (`create_orchestrator_plan` L1734, `execute_plan` L1756, `apply_orchestration_recipe` L1798, `switch_context`, `add_project_note`, `add_pane_note`, `rename_*`, `create_project`, etc.) — Every single one ends with the identical `session.sendToolResponse({ functionResponses: [{ name, id: call.id, response: { output: <text> } }] })`. That ~25× repetition is the clearest symptom of the missing dispatch table flagged in Chunk 1: a `respond(call, text)` helper (or a table where each handler just `return text`) erases ~25 copies of this line and the surrounding `let resp = ""` / branch-to-set-resp / send pattern.
- `ledger.ts:61-107` — `flushSave` (async) and `flushSaveSync` duplicate the exact same `JSON.stringify({activeProjectId, workspaces, watchRules, plans}, null, 2)` payload + temp-write + rename + dirty-on-error logic. Extract a `serialize()` returning the JSON string (and ideally a shared `writeAtomic(data, sync)`); right now a new ledger field must be added to both stringify blocks.
- `ledger.ts` — Otherwise clean and consistent: every mutator (`addProject`, `renameProject`, `renamePane`, `addPaneNote`, `addNote`, `switchContext`) follows the same guard-then-mutate-then-`save(true)` shape. Good. Note the server reaches this via `manager.ledger["save"](true)` bracket-access in several plan handlers (e.g. L1751, L1790) even though `save` is public — pointless obfuscation; call `.save(true)` directly.
- `server.ts:1798-1819` `apply_orchestration_recipe` and `create_orchestrator_plan` both build entities with the `"<prefix>_" + Math.random().toString(36).substring(2, 11)` id idiom — the SAME idiom appears for `att_`, `rule_`, `plan_`, `step_` across server.ts (8+ sites). One `genId(prefix)` helper would unify them.
- `server.ts:1100-1123` settings REST — The API-key masking (mask on GET, restore-if-masked on PUT) is a tidy, well-contained pattern. Fine.
- `src/types.ts` — Clean shared type definitions; the `PaneMeta`/`Workspace` re-export from `ledger.ts` for back-compat (D7) is reasonable. No change.
- `src/components/ProjectDialog.tsx` (226 LOC) — Not deeply audited here, but it follows the same per-field-useState dialog pattern as SettingsDialog at smaller scale; worth the same object-state treatment if touched.

## Top fixes
1. Replace SettingsDialog's ~24 field-level `useState` hooks + hydration effect + `getCompiledSettings` + dep array (`SettingsDialog.tsx:100-256`) with one `useState<SystemSettings>` object + an `update` helper — removes the four-way restatement of the settings shape.
2. Introduce a `respond(call, text)` (or dispatch-table return) to erase the ~25 duplicated `sendToolResponse({functionResponses:[{name,id:call.id,response:{output}}]})` lines across the server tool handlers.
3. Extract `ledger.serialize()` (+ shared atomic write) to dedupe `flushSave`/`flushSaveSync` (`ledger.ts:61-107`).
4. Add a `genId(prefix)` helper and replace the 8+ `"<prefix>_" + Math.random().toString(36).substring(2,11)` sites.
5. Drop the `manager.ledger["save"](true)` bracket-access in favor of direct `.save(true)` calls.
