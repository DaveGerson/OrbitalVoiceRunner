# Chunk 2 — Terminal / Pane Lifecycle & Live I/O — Maintainability

**Score: 5/10** — `ptyTransport.ts` is a clean, well-documented seam, but `terminal.ts` mixes status-machine, scrollback persistence, session-ID scraping and process control in one 400-line class, the command-mapping logic is duplicated 4+ ways, and `universal_terminal.py` is fully orphaned dead code carrying its own test.

## Findings

- **`universal_terminal.py` is DEAD CODE.** The real PTY path is `ptyTransport.ts` (node-pty / legacy child_process) consumed by `src/terminal.ts`'s `UniversalTerminal` class. The Python `UniversalTerminal` (universal_terminal.py:14) is referenced nowhere except its own `tests/test_universal_terminal.py:9`. It even re-implements `strip_ansi_sequences` (universal_terminal.py:8) with a *different regex* than `stripAnsiSequences` in terminal.ts:63 — two divergent ANSI strippers, one of them exercised only by a test of unused code. This is the single biggest onboarding trap in the chunk: a new dev will reasonably assume the `.py` file is the live PTY layer.
- **`ptyTransport.ts` is the bright spot.** The `PtyTransport` interface (ptyTransport.ts:19-30), two implementations, and the single `try{require}catch{legacy}` selection (ptyTransport.ts:43-55, 189-225) are well-factored with a header comment explaining the design and the fallback-probe consequence. Good cohesion and a clean abstraction boundary.
- **`UniversalTerminal` (terminal.ts:132-549) is a god-class with ~6 responsibilities:** PTY lifecycle, the status state machine side-effects (`applyStatusEvent`, terminal.ts:264-353), probe scheduling, scrollback file persistence (`loadScrollback`/`appendScrollback`, terminal.ts:385-412), session-ID regex scraping (`checkForSessionId`, terminal.ts:237-255), and command/flag munging. Several should be collaborators. The pure decision is correctly delegated to `decideStatus` (good), but everything else is welded in.
- **Command/preset → shell-command mapping is duplicated at least 4 times** with subtly different strings: `OrchestratorManager` constructor restore (terminal.ts:691-693: `npx @anthropic-ai/claude-code`), restart route (server.ts:700-702: `npx @anthropic-ai/claude`), `parsePresetsSafe` defaults (terminal.ts:56-58), and `CreateTerminalDialog` (CreateTerminalDialog.tsx:31-39). The Claude command literally differs (`claude` vs `claude-code`) between the constructor and the restart route. There is no single `presetToCommand(preset)` function. This is the highest-leverage DRY violation in the chunk.
- **`--dangerously-skip-permissions` flag toggling is hand-rolled string surgery in three places** (terminal.ts:196-205 constructor, terminal.ts:222-230 `setPermissionsMode`, CreateTerminalDialog.tsx:42-44) using `cmd.includes` / `cmd.replace(\` ${skipFlag}\`, "")`. The replace only strips a leading-space variant, so a flag at the start of the command would not be removed. Fragile and untested.
- **`listPanes()` and the `/api/terminals` route return `any[]`** (terminal.ts:739, server.ts:643) — the pane DTO shape is constructed by hand in `syncLedger` (terminal.ts:760-776) and again differently in the REST route (server.ts:645-655). No shared `PaneDTO` type, so the two pane representations can (and do) drift.
- **`manager.ledger["save"]` / `manager.ledger.save(false|true)`** — the boolean-flag `save()` (terminal.ts:780, 1729, etc.) is an opaque positional flag (broadcast? immediate?) with no named meaning at call sites. A new dev cannot tell what `save(true)` vs `save(false)` does without opening the ledger.
- **Restart route (server.ts:686-712) duplicates the constructor's pane-restore logic** (the preset→cmd switch) instead of reusing a shared helper, and calls `term.stop()` without awaiting the returned promise (server.ts:690) before `term.start()` — a lifecycle race the type system would have surfaced if `stop()`'s `Promise<void>` were awaited.
- **`create_pane` tool handler (server.ts:1674-1692) and the `/api/terminals` POST (server.ts:665-683) are two parallel creation paths** with different validation and different project-bootstrap behavior, both calling `addTerminal` with positional args. `addTerminal`'s 7 positional params (terminal.ts:707-714), several optional with defaults, are easy to misorder; an options object would be far safer.
- **`handoff_context_between_panes` (server.ts:1823-1856) writes a multi-line comment block to the target pane's stdin** and self-documents (server.ts:1829-1832) that it bypasses the unified gate — an acknowledged TODO(WS-G) leaky path that only checks Read-Only, not HiTL.
- **Magic numbers:** scrollback 512KB cap (terminal.ts:403), `maxBufferLines = 100` (terminal.ts:139), probe interval `500` (terminal.ts:156), SIGKILL escalation `1000`ms (terminal.ts:545) — all inline literals; some are configurable via settings, some are not, with no consistent convention.

## Test-coverage note

- **Tested:** `test_server.ts:22-44` covers basic `UniversalTerminal` (TS) spawn + input and `stripAnsiSequences`; `test_terminal_manager.ts` exists but is thin; the *status machine* (the hard part of `applyStatusEvent`) is heavily covered indirectly via `test_status_machine.ts` (which mirrors the logic). `test_universal_terminal.py` covers the **dead** Python class — wasted coverage.
- **Riskiest untested path:** the **node-pty transport spawn/IO/exit round-trip and the legacy-fallback `kill(-pid)` process-group teardown** (ptyTransport.ts:114-182) have no integration test, and neither does the restart route's unawaited `stop()`→`start()` race (server.ts:690). `stop()`'s SIGTERM→SIGKILL escalation (terminal.ts:513-547) — genuinely tricky concurrent code — is untested.

## Top fixes

1. **Delete `universal_terminal.py` and `test_universal_terminal.py`** (or clearly mark them as a reference stub). Carrying an orphaned, divergent second PTY implementation with its own green test is actively misleading.
2. **Introduce a single `presetToCommand(preset)` (and a `togglePermissionFlag(cmd, mode)`) helper** and call it from all four sites (constructor restore, restart route, `parsePresetsSafe` defaults, CreateTerminalDialog). Fixes the `claude` vs `claude-code` drift and the fragile string-surgery.
3. **Decompose `UniversalTerminal`**: extract scrollback persistence and session-ID scraping into collaborators, leaving the class to own only lifecycle + status side-effects. This also makes scrollback testable in isolation.
4. **Define a shared `PaneDTO` type** and one builder used by both `syncLedger` and `/api/terminals`, replacing the hand-built `any[]` shapes. Convert `addTerminal`'s positional params to an options object.
5. **Unify pane creation and route the handoff write through `dispatchProposal`'s gate** so `/api/terminals`, `create_pane`, and `handoff_context_between_panes` share one validated creation/write path (closes the acknowledged WS-G bypass).
