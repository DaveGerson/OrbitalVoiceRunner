# Chunk 4 — Status Detection, Monitoring, Attention & Proactive Alerts — Maintainability

**Score: 7/10** — The *probe layer* (`statusProbe.ts`, `statusMachine.ts`, `statusConstants.ts`, `notificationStack.ts`) is excellent: pure, factored, cross-platform, fixture-tested. The score is dragged down by the transition-CLASSIFIER (build-failed/error English heuristics) living inline and untested in `server.ts`, and by attention-queue state being mutated-in-place across many server sites plus recomputed all over `App.tsx`.

## Findings

- **`statusProbe.ts` is a model of testable cross-platform code.** Every platform probe splits I/O (`execSync`/`readdirSync`) from a PURE parser (`parseProcTree`/`parsePsTree`/`parseProcessList`, statusProbe.ts:117,146,248), all sharing one `buildDescendantSet`/`childrenMap` tree-walk (statusProbe.ts:73-97) so the descendant logic "cannot drift." The shell-aware busy rule is documented with the exact defect each branch fixes (e.g. C1 `cmd /c cmd` busy-forever, statusProbe.ts:227-230). The RFC-4180 `splitCsvLine` (statusProbe.ts:193-217) is a genuinely careful touch. Best-factored file in the repo alongside `pendingApprovals.ts`.
- **`statusMachine.ts` correctly isolates the pure decision** (`decideStatus`, statusMachine.ts:73-162) from the timer side-effects (owned by `UniversalTerminal`). The busy-bias/idle-debounce rules are each commented with their invariant id (I1/I2). Honest cleanup: the dead "shell prompt gate" path was collapsed and documented (statusMachine.ts:151-155) rather than left as cargo-cult.
- **`notificationStack.ts` is a clean pure reducer** (upsert/dismiss/sort, notificationStack.ts:32-61) with the shared `ProactiveNotification` shape documented as the server↔client contract (notificationStack.ts:14-27). `NotificationStack.tsx` is a tidy presentational component with proper `aria-live` (NotificationStack.tsx:23).
- **THE smear: transition classification is hardcoded inline in `detectAndTriggerTransitions` (server.ts:515-597).** The `build-failed` vs `error` decision is a wall of `lower.includes("failed to compile") || ...` / `cleanChunk.includes("Error:") || ...` English heuristics (server.ts:524-542) embedded in a server closure. This is precisely the kind of pure, fixture-driven classifier the rest of the chunk extracted into `src/*.ts` — but it was left in `server.ts`, so it is (a) not directly unit-testable, (b) duplicated in spirit by the client's `earconForAttention`/`earconForTransition` (eventBus.ts:57-79) which independently re-derive severity from `type` strings, and (c) a magic-string forest with no shared catalog of the trigger phrases.
- **`attentionQueue` is mutated in place at ~6 server sites** (`manager.attentionQueue.push(...)` at server.ts:390,415,483,577; `.find`/`.forEach` mutation at 905-916) interleaved with `pruneAttention()` + `broadcast(...)` calls that must be remembered each time. There is no single `addAttention()`/`dismissAttention()` method on the manager — the push+prune+broadcast triple is copy-pasted, and forgetting `pruneAttention()` silently reintroduces the unbounded-queue bug (BUG-035) the prune was added to fix.
- **Attention-unread filtering is recomputed inline ~8 times in `App.tsx`** (`attentionQueue.filter(item => !item.dismissed)` at App.tsx:574,595,1730,1781,2329,2367,2368,2369...). No `unreadAttention` memo/selector — every render site re-filters, and a change to "what counts as unread" requires editing eight call sites.
- **`recentlyIdled` is a parallel `Record<string,boolean>` heartbeat-animation flag** maintained in `App.tsx` (App.tsx:26,663) separate from the authoritative pane status, and consumed by duplicated status-dot className expressions in three+ places (App.tsx:2653,2659,3270,3361). The status-dot color/glow logic is copy-pasted rather than a `statusDot(pane)` helper.
- **`add_watch_rule` builds the rule object inline with a `Math.random().toString(36)` id** (server.ts:1717-1733) and the same rule shape is rebuilt in the REST route (server.ts:937-941) — two construction sites, no shared `makeWatchRule()` factory; the random-id idiom is repeated across plans/attention/watch-rules with no shared `genId(prefix)`.
- **The transition union `"idle" | "prompt" | "error" | "build-failed" | "exited"` is re-typed inline** at server.ts:519 and again as a param type at server.ts:364, and overlaps but is not identical to `AnnouncementKind` (announcementKinds.ts:19) — two near-duplicate vocabularies for the same event domain, a known prior drift source.
- **`broadcast(msg: any)` (server.ts:307)** — the central fan-out is untyped, so every `attention_updated`/`pane_transition`/`watch_rules_updated` payload is an unchecked object literal (cross-ref Chunk 1).

## Test-coverage note

- **Excellent for the probe/machine layer:** `test_status_parsers.ts` covers all three platform parsers against synthetic fixtures incl. the BUG-006 busy case, C1/C3 Windows edge cases, and the agent-at-rest tree that justifies the P0-1 gate; `test_status_machine.ts` replays the decision function; `test_status_gating.ts` covers the interactive_cli/shell probe gating against a real terminal with a fake probe.
- **Riskiest untested path:** the **`detectAndTriggerTransitions` text classifier** (server.ts:524-542) — the build-failed/error heuristics that decide whether a high-severity alert + earcon fire — has no dedicated unit test (only `test_server.ts` exercises it indirectly). A new false-positive trigger phrase, or an output that should alert but doesn't, would ship undetected. The lone `tests/fixtures/status/bug006_silent_build.jsonl` fixture is for the probe, not this classifier.

## Top fixes

1. **Extract a pure `classifyTransition(chunk, status, runtimeType): Transition` module** (with the trigger-phrase catalog as named constants) out of `server.ts:515-558`, and fixture-test it like the probe parsers. This is the single highest-leverage fix in the chunk.
2. **Add `manager.addAttention(item)` / `dismissAttention(id)` methods** that encapsulate push + `pruneAttentionQueue` + broadcast, replacing the copy-pasted triple at the ~6 mutation sites and making the BUG-035 prune impossible to forget.
3. **Introduce a single `Transition` type and reconcile it with `AnnouncementKind`** (one shared event vocabulary) so the server classifier, the bus, and the client eventBus stop maintaining near-duplicate string unions.
4. **Add an `unreadAttention` selector/memo in `App.tsx`** and a `statusDot(pane)`/`recentlyIdled` helper, collapsing the ~8 inline `filter(!dismissed)` recomputations and the triplicated status-dot className logic.
5. **Add a `makeWatchRule()` / `genId(prefix)` factory** shared by the REST and tool-call rule-creation paths.
