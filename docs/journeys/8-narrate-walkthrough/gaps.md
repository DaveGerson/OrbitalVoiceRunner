## 2. Critical and High Gaps — Detail

### J8-G1 — No secret/credential redaction (Critical)

The `getPaneSummary` call chain at `src/terminal.ts:593-599` applies exactly one transformation to raw output: ANSI escape sequence stripping via `stripAnsiSequences` (`src/terminal.ts:56-60`). The resulting plain text is wrapped in a markdown code fence and delivered, unchanged, as a Gemini Live tool response at `server.ts:1249-1254`. There is no pattern-matching pass, no allow-list of safe line shapes, and no opt-in or opt-out mechanism. Any process running in the terminal — an `npm install` printing a token, a `cat .env`, a `git push` echoing a PAT, an AWS CLI call logging credentials — will have its output forwarded verbatim to Google's Gemini Live API. This is a data-exfiltration vector that will not be visible to the operator in the eyes-off audio-only interaction model. The tool description at `server.ts:1611` says the output is "clean, redacted" — so the model has no reason to warn the operator either. This gap exists at the intersection of a missing implementation and a misleading contract, making it the highest-severity finding for Journey 8.

### J8-G2 — Lying tool description poisons model behaviour (Critical)

The Gemini model is the sole narrator in this journey. It synthesises spoken audio entirely from what the tool response tells it. The description registered at `server.ts:1611` states the response is a "clean, redacted markdown **delta**." None of these three words are true: it is not clean (raw log fragments), not redacted (no secret masking), and not a delta (full tail of the ring buffer, not a diff from the previous call). A model operating under a false description will behave differently: it will omit hedges like "this is the raw output and may contain sensitive data," it will not flag that it has already read these lines in a prior turn, and it may interpret the confidence implied by "clean, redacted" as a reason not to surface concerns. This is both a model-safety concern and a correctness defect — the tool spec and its implementation have diverged entirely.

### J8-G3 — JOURNEYS_DESIGN.md line 113 propagates false claims (High)

The design document at `JOURNEYS_DESIGN.md:113` records the Journey 8 action profile as: "Redacted terminal visual logs are analyzed and spoken back to notes." Code verification confirms all three sub-claims are false. (1) "Redacted": `stripAnsiSequences` at `src/terminal.ts:56-60` removes only ANSI codes; no redaction of secrets or paths. (2) "Analyzed": the string is returned to Gemini with zero server-side NLP, pattern matching, or structured extraction; analysis happens only inside the Gemini model using raw text. (3) "Spoken back to notes": notes are not auto-generated; `addPaneNote` at `src/ledger.ts:158-163` is called only when the operator explicitly dictates a note and Janus invokes `add_pane_note`. This document error will mislead future engineers about where the complexity should live, and conceals J8-G1 (the security gap) from design reviewers.

### J8-G4 — Fixed 20-line window with no scrollback access (High)

`getRecentOutput` at `src/terminal.ts:324-326` slices the last N items from `outputBuffer`, a ring buffer capped at 100 lines (`src/terminal.ts:68`). `getPaneSummary` calls it with `limit=20` (`src/terminal.ts:593`). The pane simultaneously maintains a persistent scrollback log file at `.janus_scrollback_<id>.log` capped at 512 KB (`src/terminal.ts:204-218`), which may hold thousands of lines — but `getPaneSummary` never reads this file. The Gemini tool surface exposes no `limit`, `offset`, `after_line`, or `keyword` parameter on `get_pane_summary` (`server.ts:1612-1619`). For any build or test run producing more than 20 lines of output, the operator hears only the tail. Errors that occurred mid-run are silently outside the window. The operator cannot say "go back further" or "find the first error" — there is no tool to satisfy that request.

### J8-G5 — No delta tracking: re-calling produces the same narration (High)

Every invocation of `get_pane_summary` returns `outputBuffer.slice(-20)` unconditionally (`src/terminal.ts:324-326`). Neither `UniversalTerminal` nor `OrchestratorManager` stores any cursor, watermark, or "last summarised at line N" state. If the operator says "anything new since you last checked?" Janus will call `get_pane_summary` again and receive exactly the same 20 lines (assuming no new output), producing an identical narration. The tool description calls the output a "delta" (`server.ts:1611`) but no delta mechanism exists anywhere in the codebase. The natural operator use-case — checking in on a running build every few minutes — is broken because each check sounds identical to the last, giving no signal about whether the process has progressed.

### J8-G6 — Raw log noise is audio-hostile (High)

The 20-line text slice handed to Gemini may contain timestamps, hex memory addresses, base64 fragments, URL-encoded strings, repeated progress-bar update lines (which blank-line filtering at `src/terminal.ts:279` partially but not fully suppresses), and verbose module path output. Gemini will attempt to speak these aloud. There is no server-side extraction pass that identifies `error:` / `Error:` / `FAILED` / `WARNING` / `npm ERR!` patterns or non-zero exit codes before sending the payload to the model. An operator working eyes-off cannot skim; every syllable of the narration is cognitive load. The current design forces Gemini to narrate raw terminal noise rather than a structured signal, which is the opposite of the "coherent, human-readable spoken narration" described in the deep-dive's ideal experience section.

### J8-G10 — Silent note loss on bad pane ID (Medium)

`addPaneNote` at `src/ledger.ts:158-163` guards its work with a compound conditional and silently returns `undefined` if either `projectId` or `paneId` is not found in `this.workspaces`. The server handler at `server.ts:1342-1347` does not inspect any return value from `addPaneNote`; it unconditionally sends `{ output: "Note added to pane ${args.pane_id}" }` to the model. If the model passes a stale pane ID (e.g., a pane that was deleted since the session started, or a typo in the ID from speech recognition), the note is silently discarded and both Janus and the operator believe it was saved. In an eyes-off session there is no visual feedback that would catch this.

## 3. What's Solid

**Note persistence infrastructure is complete and robust.** Both `addPaneNote` (`src/ledger.ts:158-163`) and `addNote` (`src/ledger.ts:181-186`) write to a structured JSON ledger using an atomic temp-file rename pattern (`src/ledger.ts:89-127`), preventing corrupt writes on crash. The `broadcastLedgerUpdate()` mechanism (`server.ts:1344`) pushes the updated ledger to all connected clients over WebSocket immediately, and the React client applies it in `App.tsx:897-898`. Notes are displayed in two UI locations (sidebar pane cards and the buffer panel), and REST endpoints exist for programmatic access (`server.ts` ~634-653). The note-capture half of Journey 8 is fully functional.

**ANSI stripping is correct.** `stripAnsiSequences` at `src/terminal.ts:56-60` uses a well-formed regex covering all standard ANSI CSI sequences. The result is genuinely plain text — colour codes and cursor-movement sequences will not be spoken aloud.

**Ring buffer overflow is handled correctly.** The `outputBuffer.splice` pattern at `src/terminal.ts:281-283` and `src/terminal.ts:298-300` keeps the buffer at exactly `maxBufferLines` lines without leaking memory, and the scrollback file has its own 512 KB cap with pruning at `src/terminal.ts:209-213`.

**Pane-note and project-note tool declarations are correctly formed.** `add_pane_note` and `add_project_note` at `server.ts:1632-1655` both declare all required fields and the handlers correctly call the matching ledger methods. The model can capture notes in either scope without ambiguity.

**The shallow `getPaneSummary` test in `tests/test_server.ts:91-99` does confirm the basic contract** — markdown fence wrapping and content inclusion for a live terminal — even if it is insufficient for the full journey scenario.
