## 2. Critical and High Gaps — Detailed Analysis

### J5-G1 — Global override silently nullifies per-pane demotion (Critical)

This is the most dangerous gap in the permissions model. The effective-mode resolution at `server.ts:1272-1275` is a two-branch conditional: if `manager.globalPermissionsMode` is any value other than `"Inherit"`, the pane's own `permissionsMode` field is never read and has no effect on whether a proposed command is executed, blocked, or held for approval. The `set_pane_permissions` handler at `server.ts:1542-1557` performs its ledger write and runtime update unconditionally and then returns the string "Safety permission mode for pane X updated to Y successfully." It does not inspect `manager.globalPermissionsMode` at all. The consequence is that an operator who has their global pinned to `"Full Auto"` (a common default when running trusted agents) and then says "Janus, drop the deploy pane back to review mode" will hear a confident spoken confirmation from Janus while every subsequent command on that pane continues to execute automatically without any human gate. Neither Janus, the UI, nor the server logs produce any signal that the requested change was a no-op for command gating. This is a silent safety regression — the operator's trust posture is betrayed. The same failure mode applies in reverse: an operator with global set to `"Human-in-the-Loop"` who promotes a pane to `"Full Auto"` will hear confirmation but no commands will auto-execute. The fix requires the handler to read `manager.globalPermissionsMode` and either reject the call with an explanatory error response, or complete the write while appending a spoken rider that tells the operator the change will have no effect on gating until the global is changed to `"Inherit"`.

### J5-G2 — `--dangerously-skip-permissions` flag deferred to restart, not live PTY (High)

`UniversalTerminal.setPermissionsMode` (`src/terminal.ts:118-130`) correctly appends or removes the `--dangerously-skip-permissions` flag from `this.shellCmd`. However `this.shellCmd` is only consumed by `start()` at `src/terminal.ts:228`, which reads it to build the `spawn()` argument list. A pane promoted to Full Auto mid-session therefore has its runtime process still operating under whatever permission mode it was launched with. For Claude Code and Codex presets (which default to `dangerouslySkipPermissions: false`, `src/terminal.ts:49-50`), this means the subprocess continues to prompt for individual tool approvals internally even though the orchestrator will pass commands without waiting for human approval at the `propose_command` gate. The result is a split-brain state: the orchestrator layer says Full Auto but the subprocess layer says Human-in-the-Loop. There is no restart voice tool (`server.ts:1576-1834` contains no `restart_pane` declaration), so the hands-free operator cannot complete the promotion without opening a browser tab to click the UI restart button — defeating the eyes-off promise of the journey. The REST endpoint at `server.ts:537-545` exists and is correctly wired, but it is inaccessible to Janus.

### J5-G3 — No audio earcon or spoken prior-state echo on autonomy transition (High)

The earcon/notification pipeline in `src/App.tsx` distinguishes four security-relevant events — `approval_pending` (alert earcon, `App.tsx:877`), `command_auto_executed` (execute earcon, `App.tsx:905`), `command_blocked` (alert earcon, `App.tsx:911`), and errors (alert earcon, `App.tsx:923`) — but the `terminals_updated` event emitted by `set_pane_permissions` at `server.ts:1554` triggers only a silent `fetchTerminals()` call at `App.tsx:896` with no earcon, no toast notification, and no spoken summary of the previous mode. For a voice-only, eyes-off operator, the mode transition is therefore indistinguishable from any other background state poll unless Janus's spoken response happens to include the old mode. The system instruction (`server.ts:1568`) does not instruct Janus to echo the prior state, so it will not do so unless the operator specifically asks. This gap combines with J5-G1 to create a scenario where the operator hears a confident "Done" for an ineffective change, with no audio fingerprint to distinguish "changed and effective" from "changed but overridden."

### J5-G9 — No `restart_pane` voice tool — Full Auto flag change cannot be completed hands-free (High)

The Full Auto promotion pathway for Claude Code and Codex presets requires two steps to be fully effective: (1) update `permissionsMode` so the orchestrator gating passes commands automatically, and (2) restart the pane so `--dangerously-skip-permissions` is injected into the subprocess. Step 1 is available as a voice tool. Step 2 is not. The REST API at `server.ts:537-545` correctly calls `term.stop(); term.start()`, which will re-spawn the process using the updated `shellCmd` that now includes the flag. But this endpoint is not declared as a Gemini function tool in the tool list at `server.ts:1576-1834`. An eyes-off operator is therefore stranded mid-journey: Janus can confirm the intent but cannot execute the second step, forcing a keyboard/mouse interaction that violates the hands-free contract of the system.

## 3. What's Solid

The foundations of the permissions model are well-engineered. The `propose_command` effective-mode resolution at `server.ts:1271-1275` is correct and defensive: it defaults to `"Human-in-the-Loop"` if the terminal object is missing, preventing an unintended Full Auto fallback on a stale or missing pane. Ledger writes use an atomic write-then-rename pattern (`src/ledger.ts:89-98`, `src/ledger.ts:113-122`) with a 100 ms debounce, preventing corruption from rapid sequential changes. The dual-path write in `set_pane_permissions` (runtime `term.setPermissionsMode` plus ledger direct mutation at `server.ts:1544-1552`) and the identical REST path at `server.ts:655-673` ensure that voice and UI changes are symmetric in effect and both survive restart. The `--dangerously-skip-permissions` flag management in `setPermissionsMode` (`src/terminal.ts:118-130`) correctly handles both the add and remove cases and guards against double-appending. The `Human-in-the-Loop` flow is fully implemented end-to-end: commands are held in `pendingApprovals`, an `approval_pending` WebSocket event with earcon is fired, and the `approve` REST endpoint at `server.ts:991-1023` correctly routes the response back to the Gemini tool call. The `Read-Only` block path (`server.ts:1304-1317`) sends both a tool error response and a `command_blocked` broadcast with earcon. The `Antigravity` preset correctly defaults to Full Auto with the skip flag baked in, consistent with its designed use case. Per-pane `permissions_mode` is preserved in the ledger's `PaneMeta` interface (`src/ledger.ts:12`) and survives server restarts via the load/restore path in `OrchestratorManager` (`src/terminal.ts:504-518`).
